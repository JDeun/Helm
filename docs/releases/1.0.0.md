# Helm 1.0.0 — 2026-09-28

## Why this is 1.0

Helm shipped four unprefixed top-level packages: `scripts`, `commands`, `references`
and `memory_tree`. Two of those are among the most common directory names in Python
projects, so installing helm-agent-ops could shadow a user's own package — their
imports break and nothing points at helm as the cause.

It was not hypothetical. It happened to helm's only user: a workspace `scripts/`
package was shadowed by helm's, producing 14 pytest collection errors, and because a
single collection error aborts the whole run it also hid every other result.

## What changed

| before | after |
|---|---|
| `scripts` | `helm.scripts` |
| `commands` | `helm.commands` |
| `references` | `helm.references` |
| `memory_tree` | `helm.memory_tree` |
| `helm.py` (module) | `helm/` (package: `helm/cli.py` + lazy `helm/__init__.py`) |

443 import sites across 158 files were rewritten. The installed distribution now
claims exactly one new top-level name — `helm` — permanently.

## Migration

```python
# before
from scripts.run_with_profile import run
from commands.checkpoint import cmd_checkpoint_create

# after
from helm.scripts.run_with_profile import run
from helm.commands.checkpoint import cmd_checkpoint_create
```

There is no compatibility alias. Aliasing `scripts` to `helm.scripts` would preserve
the collision and defeat the change.

## Unchanged

- The `helm` console script and every subcommand verb.
- `import helm; helm.main([...])`, `helm.build_parser()`,
  `helm.build_status_payload()`, `helm.build_state_snapshot_payload()`.
- `helm_workspace`, `helm_context`, `helm_state_model`, `helm_frontmatter` remain
  top-level modules — they are already `helm`-prefixed.
- Workspace-relative reference lookups (`<workspace>/references/...`).
