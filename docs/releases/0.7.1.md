# Helm v0.7.1 — Lifecycle Polish

**Date:** 2026-05-03

Helm 0.7.1 finishes the gaps identified in the v0.7.0 PRD review: the
remaining curator commands (ledger correlation, mtime/atime observer,
manual view event), persisted negative-claim metadata, richer umbrella
clustering, and matching workspace-side polish for the AI tech briefing
deduplication gate and the skill eligibility report.

This is a backward-compatible polish release on top of v0.7.0. No public
schema or CLI behavior was removed.

## Added

- `helm skill-lifecycle ledger` — joins lifecycle events with rows from
  `<workspace>/.openclaw/task-ledger.jsonl` by `task_id` so `task_name`,
  `task_status`, `exit_code`, `started_at`, `finished_at`, and `profile`
  are visible inline with each event
- `helm skill-lifecycle observe` — polls every tracked SKILL.md, emits
  `skill_patched` (mtime advance) and `skill_viewed` (atime advance) and
  baselines silently on first invocation per skill
- `helm skill-lifecycle view <skill>` — manual `skill_viewed` event,
  atime-independent; useful when filesystem atime is deferred or
  disabled (e.g., macOS APFS)
- `helm skill-lifecycle negative-claims --persist` — writes detected
  claims into per-skill `negative_claims` metadata using the PRD shape
  (`claim_id`, `text`, `keyword`, `detected_at`, `last_revalidated_at`,
  `ttl_days`, `confidence`, `status`); idempotent, preserves manually
  edited fields across re-runs
- umbrella detection signal types: `name_token` (existing),
  `description_token` (Jaccard-style across SKILL.md frontmatter
  description), and `downstream_share` (skills referencing the same
  downstream skill in backticks); each cluster carries a `signal` field
- report sections: `## Pin Candidates` (active unpinned skills with
  `use_count >= 3`) and `## Recommended Actions` (action items derived
  from the surfaced candidates)

## Changed

- briefing dedup gate (workspace `scripts/briefing_dedup_check.py`)
  now also searches `~/.openclaw/memory/main.sqlite` (`chunks_fts` FTS5)
  and `~/.openclaw/workspace/.openclaw/task-ledger.jsonl` (last 7 days
  by default). Verdicts gain a `sources` breakdown
  (`obsidian_notes` / `obsidian_web` / `memory` / `task_ledger`);
  `existing_notes` retained for back-compat. Placeholder URL hosts
  (`example.com`, `localhost`, `0.0.0.0`, etc.) are filtered out of
  URL needles to prevent false positives. New flags
  `--ledger-lookback-days N`, `--no-memory`, `--no-ledger`.
- eligibility report (workspace `scripts/skill_eligibility_report.py`)
  now reads lifecycle metadata and shows per-skill `state`, `pinned`,
  `use_count`, `last_used_at`, and `source`, plus an aggregate summary.
  New `--json` mode. Falls back gracefully when the lifecycle layer is
  not initialized.
- umbrella `description_token` clusters now cap at ~25% of total skills
  to filter generic words; English/Korean stopword list expanded to
  include common verbs (need, want, make, get, find, ...) and Korean
  function words (사용, 필요, 관련, ...)

## Tests

- 55 lifecycle test cases (12 added since v0.7.0): pin candidates,
  recommended actions, persisted negative claims (idempotency + status
  preservation), umbrella signal richness (description / downstream /
  generic-token filtering), task-ledger correlation, observer (baseline
  / mtime advance / dry-run / uninitialized fallback), and the manual
  `view` event path
- full suite: 364 tests passing

## Validation

- smoke-tested against `~/.openclaw/workspace`: ledger correlation
  surfaces task_name + status + exit_code for the prior `inspect_local`
  car run; persisted negative-claim metadata covers 32 candidates
  across 12 skills; umbrella reports 19 actionable clusters
  (2 name_token, 15 description_token, 2 downstream_share) versus the
  pre-fix 122; placeholder-host filter eliminates the `example.com`
  false-positive control case

## Migration

No migration required. Workspaces that already ran v0.7.0
`helm skill-lifecycle scan` keep working; the new commands and fields
are additive. To populate the new persistent negative-claim metadata,
run `helm skill-lifecycle negative-claims --persist` once.
